# v3 独立美术接入说明

本轮从整屏概念图补足到独立素材组成树。当前制作/验收状态读取 `production/completion-status.json`，不把本文或文件已存在当作终检通过。

组成树的设计画布为1600×900，每个叶层有 `type`、`rect=[x,y,width,height]`、独立 `file` 或原生 `text`，另有 `binding`、按钮皮肤状态、交互可用性与可选跳转。列表值、昵称、日期、数量、倒计时和分数都用原生文字。样例值不能作为规则、真实在线状态或已发放奖励。

## 图层与缩放

背景等比cover；人物、图标、牌面、表情及珠饰卡框等比contain。窗框与正文框只按清单约定九宫格。按钮、输入描边与新增列表皮肤先统一缩小到目标行高，再只横向九宫格，不能分别挤压两侧云纹。所有目标尺寸表示显示排布，不把屏幕组合或九宫格拉伸称为新增原生细节。

图层依数组顺序由后向前绘制。背景→正文填充→窗框/标题→列表和牌桌层→角色、原生文案、操作控件→候选/提示→模态层；滑条填充位于滑块下方。`sourceRect` 为源图片的 `[left,top,right,bottom]` 裁切矩形，用于去掉纯透明补边后安放纯填充/滑块；它不同于显示 `rect` 的宽高口径。`clipFraction` 在完整目标填充上从左到右裁剪，0时完全隐藏，不能把填充本身缩短而挤压装饰。

RGBA按目标引擎的直通/预乘设置导入并保留透明边距。现有深浅底结果只证明源文件轮廓；图集挤出、纹理压缩、分辨率安全区和设备滤波在目标工程再次验收。交付包不分发系统字体二进制，工程应使用已有授权的中文字体并按 `fontSize`/行高适配；不能依赖整屏中烘焙的中文。

## 对局与数据绑定

四座按 `runtime-compositions.json` 的显示槽与旋转排布，整张牌和字形一起旋转，不能镜像。暗手及暗杠隐藏位显示独立牌背。两层牌墙、弃牌网格、副露横置来源牌和加杠堆叠均有独立组合；示例重复使用六萬只用于检查方向，不定义真实牌序或牌池数量。

当前玩家、庄家、倒计时、离线、托管分别绑定。离线与托管是不同标志，可以同时成立；不能互相替代或仅靠颜色表达。动作按钮只按真实合法候选激活；空候选、提交中、过期都禁用确认，选中ID必须在提交前重新核对。听牌剩余张数没有真实数据时隐藏，不能据美术示例牌推断。

单局和整场结果四家分别绑定 `result.players[0..3].name/portrait/score`。正分朱砂红带+号、负分玉绿带−号，0分中性色；输赢、流局、自摸与普通0分分别有文字/提示资源。示例积分并不确认地方计分规则。

## 人物、装扮与系统状态

角色详情是可换数据的模板。用 `selectedCharacterId` 索引 `charactersById`，分别读取 `fullBody`、`displayName`、`description` 和 `expressions`；四个表情标签统一为开心、思考、惊讶、沮丧。已有UI26概念图中的旧标签留作历史设计证据，运行模板不沿用其错误标签。脚底锚点按角色清单使用，不能将透明画布底当作脚底。

桌面和牌背为不同纹理槽，各自使用主题绑定中的真实路径。预览选择与已应用状态分开；相同选择显示已使用，或按工程约定做幂等应用。概念图中的缩略图不能作为最终纹理源。

邮箱读取不自动领取。领取待回执时锁重复提交，成功后改已领取并移除可领取动作；空邮箱不保留上条详情。房间满员禁邀请，全部准备且满足房主条件才亮开始。断网、重连、恢复失败、匹配中/成功/取消/超时采用不同文案与操作可用性。

## 检查与交付边界

组合检查图由真实独立素材与文字确定性排版，1280×720输出只是1600×900画布的缩小检查图。逐图记录保存源PNG哈希、组成树内容哈希与渲染脚本哈希；这些任一变化必须重新生成对应检查图。旧图像哈希不变的通过结论继续复用。

`production/gallery-validation.json` 仅记录离线脚本/路径检查；本地浏览器策略已明确拒绝文件访问，没有通过服务器、换协议或其他浏览器绕行。当前资料不声称实际游戏客户端、网络服务或目标设备已经验收。

通过最终检查后按已授权的公开仓库发布，保持main一个无父提交，使用明确旧远端SHA的约束更新。未通过项保留真实pending，不能为了上传而改成通过。
