# 完整麻将游戏美术交付 v2

用户于2026-10-26明确要求达到“完整游戏全部美术完成程度”，随后再次要求继续。本轮沿用已完成UI包，补齐通用四人横屏2D麻将所需的独立素材，不能再以UI页面完成代替全游戏美术完成。

## 产品假设与交付对象

默认16:9横屏、四人休闲匹配与好友房，高清手绘2D角色立绘配表情，动态交互由独立切片与特效时间轴呈现。正式游戏名、地方番型和付费系统未指定；不虚构收费。花牌、排行榜、成就和物品收藏提供可选模块美术，不强制开启玩法。角色无跑跳战斗需求；本合同不以角色战斗动画或影片替代麻将桌游素材。

原24个UI合同ID、27张界面/状态图、58项组件、34种基本牌面、原有角色与记录继续有效。已有哈希不变的通过结果复用，不重生成。

## 分工与文件所有权

- root：本合同、场景/牌桌/牌背/标识、统一画廊、总清单、独立验收与完整包。
- full_ui_scope_audit：`assets/characters/full-game`及对应设计/提示词/记录。
- mahjong_tiles_pack：`assets/props/full-game`、`assets/tiles/flowers`及对应设计/提示词/记录。
- full_game_fx：`assets/fx/full-game`及对应设计/提示词/记录。
- 用户的独立制作聊天：`designs/ui/full-game`、`assets/ui/full-game`及对应设计/提示词/记录。

各域不覆盖旧的manifest或其他域在制稿。生成仍使用用户指定的内置image_gen入口，配置目标GPT Image 2.5 Sunburst/max；工具不披露时实际型号和质量继续写未确认。每张图附主参考、提示词、来源哈希、真实尺寸、检查结果；裁切/缩放/排版写derivedFrom与实际操作。

## 最终验收

每项必须对应真实文件、记录和通过结果；独立抽查各域视觉、深浅底透明、文字/牌语义与方向；统一校验哈希、尺寸、状态、依赖、包内文件。提供可浏览本地画廊、客户端接入文档和新完整ZIP。新包验收后再按素材保留规则处理被替代的旧中间稿，不删除仍在引用的必要原画。

没有客户端工程与服务端接口，因此美术交付和真实游戏接入分别标记。文件浏览器被策略阻断，不通过改协议或其他浏览器绕行；图片实看与静态画廊检查如实记录。远端上传地址尚未提供，全部成果保存在本项目，不宣称上传。
