2026-10-26，按 FULL_UI_SCOPE 的牌面组合同独立制作。范围为 34 种基础牌、统一空白牌胚与玉绿太极牌背、符号矢量层、状态/朝向映射与检查预览。

基础使用位图共 37 张（34 牌面、2 牌胚/背、1 状态外框）；另有 34 张独立符号 PNG 和 2 张检查预览。**所有基础使用位图和符号层都是 448×640 RGBA PNG**，共享透明画布，牌面主体完整。文字已转为字形路径，符号 SVG 不依赖运行设备安装楷体。

手绘空白牌胚、牌背的原生输入均为 1024×1536 RGBA。最终版对原生 Alpha 取 `>=128` 的实际牌体轮廓、裁除外部低 Alpha 光晕并等比缩小，最后居中到 448×640；Lanczos3 缩小产生窄边抗锯齿。此为确定性透明轮廓整理与导出，不是新模型绘画，未放大或冒称原生 4K。牌面牌体实际约 432×600，牌背约 418×600，均保留原比例；精确内容边界见 manifest。

## 风格与语义

实际查看并附入邮件、组队两张主参考，以米白、玉绿、暖金和细腻手绘牌体延续道家 Q 版。牌背使用太极与云纹。牌面文字与筒/条数量采用精确原生矢量排版，避免生成模型造成数字或符号数量错误。

- 万子用中文一至九和传统牌字“萬”。
- 东南西北为深青字，中为朱砂红，“發”为玉绿；白板使用蓝色空框，与空白牌胚明显区分。
- 一条使用**一根完整竹节**，与二至九条一致，非鸟牌版本。其语义在整套联系表和标签中清楚可认。
- 八种花牌未混入通用规则，本批不含花牌。

## 朝向、尺寸和状态

以下角度指屏幕坐标中顺时针旋转，字头朝牌桌中心：自家位于屏幕下方时 0°，左家 90°，对家 180°，右家 270°。整体旋转牌面，**不镜像字形**。对手暗手只显示同朝向牌背；明牌/弃牌/副露才显示相应牌面。

建议本人手牌显示为 112×160、间距约 96；弃牌/副露约 45×64，按屏幕密度调整。全牌等比缩放，不能用九宫格拉伸。默认中心枢轴 `(0.5,0.5)`；手牌上抬时可用底部枢轴 `(0.5,0.95)`。

- 正常：白色顶点色、Alpha 1。
- 选中：整体上抬，112×160 显示规格建议上抬 12px，按需叠加高亮外框。
- 可操作：叠加 `states/tile-highlight.png`，不用更换牌面身份。
- 不可打/禁用：整体去饱和、亮度 0.60，保持原 Alpha；状态映射中记为不可交互。
- 悬停：可提高亮度至 1.06；具体交互由客户端实现。

状态预览中的“六万”用于可视检查左右朝向；不使用旋转对称牌型掩盖朝向错误。

## 生成与来源

使用内置 image_gen，共 3 次调用：空白 v1、空白 v2 清理尝试、匹配牌背。配置目标为 GPT Image 2.5 Sunburst/max；本次工具无型号/质量选择器，也未返回可核实版本，实际值均记录为未确认。精确符号不是 34 次独立模型生成。

- 被采用的两个原生输入位于 `assets/tiles/source/tile-blank-v2.png` 与 `tile-back-v1.png`，各有同名生成记录。
- v1 空白为已被替代的编辑输入；最终成品落盘后，已删除其项目内图片，只保留 `tile-blank-v1.png.generation.json`、哈希、提示词与清理说明。后续来源记录明确该图像字节已不在项目内。
- 三次实际提示词在 `prompts/tiles/`。
- 每张成品 PNG 旁有 `.generation.json`，记录真实派生操作、源图哈希及符号 SVG 哈希；符号 SVG 的 `.asset.json` 记录文字、颜色和数量语义。
- `source/glyph-outlines.json` 保存 16 个所用字形的矢量路径；来源为本机楷体轮廓，没有分发字体文件。

## 检查与接入边界

已对 34 张牌面作画布、文件哈希、真实 Alpha、透明上下边距、中心不透明与唯一性检查。另以**渲染后符号 PNG 的像素连通域**独立数出全部 9 张筒和 9 张条的符号数量，18 项均与牌值一致。整套联系表已实际逐张查看，另有独立审查者视觉复核；深浅底边缘清楚，未发现阻塞问题。朝向修正后的检查以 validation.json 最终记录为准。

这是美术及使用映射交付，尚未接入实际客户端。字形、牌面与示意位置不定义地方麻将的番型、花牌、计分或可操作规则。

重建工具位于 `assets/tiles/tools/`：先以本机楷体运行 `export-font-paths.ps1`（已有轮廓文件可跳过），再用带 sharp 的 Node 运行 `build-tiles.cjs`，用带 Pillow 的 Python 运行 `verify-and-preview.py`。重建不调用模型，不需 API 密钥。重建后视觉状态会重置为待复核，应重新核对变化文件。
