# 2026-10-28 运行 UI 美术缺口审计

本次审计读取 32 个 UI 合同 ID、75 条状态、总资源清单、80 项 UI 组件（原 58 项与新增 22 项）及 `assets/ui/component-compositions.json`。未修改旧美术、旧清单或 Git。目标是能组合真实界面的有限原子皮肤，不增加收费、玩法或角色。

## 核心结论

75 条状态中 60 条总清单映射只指向 `designs/`，这证明有视觉示例，不能独立证明有运行组件；但也不意味着缺 60 张图片。现存 composition 已覆盖开关、进度、输入、六位房号、弹窗、按钮与部分列表组合。多数状态应使用原生文字、已有组件与实际数据绑定，无需重新生图。

P0 应补齐明确的运行组合映射与独立、适配目标用途的皮肤：专用进度/滑条填充、专用开关轨道与滑块，以及不污染输入内容的 focus/error 叠层和列表选中/按下底板。空态六插图由根协调者生产，本域不重复。其他页面可复用原 58＋22 项，不重画整屏。

## P1：有限补齐建议

- 现有 `content-card` 九宫格最小 91×91、`input-field` 最小 69×61、`window-frame` 最小 401×401（源像素口径）；若客户端真需要更小弹窗，先统一缩小整体再九宫格，不另生一整套窗框。
- 列表分割线、禁用灰化、在线/忙碌状态圆点、文字下划线、输入光标、焦点键盘可达反馈可用原生 UI 几何/文本，不必生图；须在运行合同明确实现。
- 当前动态文案没有随引擎打包字体文件；选用已获授权的目标字体、记录行高与 fallback 是接入项，不能将整屏烘焙文字当可编辑字体资产。
- 角色/图标/牌面/带玉珠卡框必须等比，新增 22 项 `resizePolicy=uniform_scale_only` 不能因矩形外观私加九宫格。
- `keypad-key` 与 `content-card` 字节相同，是可复用别名而非两份独立原画；后续统计按文件内容/用途如实区分。

## 本批建议切片合同

1. 母图落 `designs/ui/production-v3/forms/`，实际原生尺寸与 model/quality 证据逐图保留；工具无选择器时 model/quality 都是 null。
2. 切片落 `assets/ui/production-v3/forms/`，每项有 `derivedFrom`、原生裁切框、透明处理、输出尺寸、锚点、最小几何、九宫格与缩放限制。
3. 输入叠层/列表底板只在保边且中心规则足够简单的区域采用九宫格；外圈云纹固定。圆滑块等比。进度/滑条填充只横向伸缩/裁剪，不能将进度数值烘焙进图。
4. 测试组合需展示输入正常/焦点/错误/禁用、列表正常/选中/按下、progress 0/25/50/100%、toggle on/off/disabled、slider 0/0.5/1。不同状态同画布，不随包围盒跳位。
5. 深浅底实看、透明边缘/空洞、裁切完整性与来源哈希通过后再登记 passed。状态图有记录但不可点击，不等于真实客户端已接入。

本审计未扩展收费、地方玩法或更多角色；根代理负责跨域整合、实际客户端流程与最终发布。
