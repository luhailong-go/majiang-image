# 麻将 UI 美术接入说明

本包交付页面美术、透明组件、牌面、角色、状态映射与来源记录。本地 index.html 仅用于浏览交付文件；没有连接真实账号、匹配、牌局、积分或回放服务。正式游戏名称与地方规则尚未确定。

## 画布与文件用途

- 默认横屏 16:9。独立生成整屏以各文件实际原生尺寸为准，当前常用 1672×941，接近 16:9；不把目标 2048×1152 当作实际返回尺寸。
- designs/ui/full-suite 内的整屏与状态规范板用于页面结构和美术评审。UI23、UI24 是规范板，板内小项不冒算独立整屏。
- assets/ui 内的透明控件才是组合界面的素材。文字、金额/积分、倒计时、头像内容和动态牌面应使用独立层，不把整张屏幕截图作为可拉伸窗口。
- 九宫格、锚点和推荐用途以组件 manifest 为准。窗框/按钮可按边距九宫格伸缩；人物、头像、图标、牌面必须等比显示。
- assets/characters/welcome-daotong.png 是修净后的正式透明立绘；designs/characters/production 内图片为生成来源，不能仅凭 production 文件名跳过 Alpha 清理记录。
- 牌面使用 assets/tiles/manifest.json 中登记的34张标准面和牌背/牌胚。整屏中的小型牌面只表达视觉布局，不作为可裁出使用的牌面资产。

## 数据、状态和可用性

昵称、房号、积分、局数、日期及牌局为布局样例，不是线上用户数据或已确认计分合同。通用四人好友房与休闲匹配是本轮设计假设。

操作可用性必须由真实游戏规则与服务端状态决定；UI10 同屏展示碰/杠/胡/过是控件示意，不能据此让四项始终同时可点。多个候选组合、听牌内容、托管、庄家、当前玩家与倒计时分别绑定状态。离线和托管不可混为同一状态。

房间准备、开始条件、解散投票参与者/进度/结果、加入失败和重连恢复均有页面或规范板来源。状态清单位于 exports/ui-delivery-manifest.json；组件皮肤的正常/按下/选中/禁用映射位于组件 manifest。流局使用专门的状态来源，不能复用“胡牌”字样。

邮件领取、好友邀请/申请、账号操作和回放入口需要真实回执。等待时禁用重复提交，成功后更新已领取/已邀请/已处理，失败回到可重试状态；实际错误原因使用真实服务信息。

## Alpha、图集与缩放

透明图片使用真实 RGBA。导入时按直通 Alpha 处理并验证预乘设置，检查深浅底边缘；图集保留透明挤出与合理留白，避免相邻图块采样串色。角色最终导出的原生来源、低 Alpha 清理与透明补边均记录为派生操作，未冒称生成原生1536细节。

手牌通常使用竖向正面牌，弃牌/副露使用等比缩小牌；其他座位朝向根据牌面 manifest 的方向方案旋转，不能在符号未同步时只旋转底图。暗手使用统一牌背。选中/高亮/不可打应分离状态层和交互状态，不永久改写原牌面。

## 复核与交付边界

每张生成图与派生文件的来源、尺寸、SHA-256、提示词和视觉/技术检查见相邻记录。配置目标为 GPT Image 2.5 Sunburst/max；内置工具未公开可核实实际型号与质量，因此实际字段保持 null。

当前仅本地交付，未配置远端、未上传；没有修改原 image 仓库或客户端工程。完整美术交付不等于真实麻将客户端、服务端或线上业务验收。



## 通用色彩与积分语义

| Token | 推荐值 | 用途 |
|---|---|---|
| score.positive | #B52F20 朱砂红 | 正积分，数值保留 + 号 |
| score.negative | #196448 玉绿 | 负积分，数值保留 − 号 |
| score.neutral | #6F6654 暖灰褐 | 0分、不变、说明文字 |
| action.primary | #165B4A 玉绿 | 主要操作底色 |
| text.primary | #183D35 深玉绿 | 正文与次操作文字 |
| surface.paper | #FFF9E9 象牙米白 | 信息面板与卡片 |
| border.gold | #BCA16A 暖金 | 边框与分隔 |
| state.disabled | #A8A18E 灰米色 | 不可用控件及文字 |

积分颜色语义在单局/整场结算、战绩列表/详情中一致。正负号与文字同时表达结果，不能只用颜色区分。生成图存在手绘明暗，以上为动态原生文字与客户端主题的规范值，不把截图每个像素当作精确色值。
