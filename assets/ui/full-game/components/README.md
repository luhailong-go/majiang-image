# 完整游戏 v2 新增组件

本域交付 22 张独立 RGBA PNG，来自 4 张内置 image_gen 透明母版。全部采用原生像素机械裁切与透明清理，未放大。已有的 58 项通用/对局组件没有重做；本清单列出其中 23 项复用引用。

入口为 [manifest.json](manifest.json)、[compositions.json](compositions.json) 和 [qa.json](qa.json)。每张 PNG 的同名 `.generation.json` 保存来源文件与哈希、原生尺寸、裁切范围、Alpha、留白、锚点和缩放约束。

## 透明与裁切

卡片和物品槽外部透明，内容区为米白实底。成就框、聚光圆环和焦点框中心为真实透明；没有棋盘格或棕色背景烘焙。圆环保留有意的柔金色外发光。

机械导出先清除 Alpha≤8 的低透明像素与不含 Alpha≥128 主体的孤立区域，把 Alpha≥250 归一到255，并清零 Alpha0 下的 RGB。每张母版清理后恰好留下计划中的独立连通主体，所有主体均导出一次，Alpha≥128 像素零删失。随后根据实际连通主体裁切，避免按均分网格切断徽章尾饰。最终每侧透明边距至少16像素。

## 布局与缩放

全部新增切片的 `nineSlice` 为 null，`resizePolicy` 为 `uniform_scale_only`。云角、玉珠、徽章、缎带和指引图形都等比显示。需要其他比例的内容区时，应调整布局或使用旧版已经批准九宫格的内容卡，不能横纵分别拉伸本批装饰。

同族状态共用画布尺寸与中心锚点，保留手绘状态之间的小幅轮廓差异。物品槽四态统一660×508；新获得缎带向右突出，导出按卡片主体中心对齐，并给全部状态保留相同画布。不要再次按每张非空边界居中，否则切换状态会漂移。

所有中文、数字、名次、道具数量、步骤和活动信息由客户端原生层提供。奖励“待领取”与“已领取”是互斥状态；已领取状态隐藏领取操作。装扮选中和实际使用中按业务状态区分，禁用物品槽同时关闭交互。具体绑定、安全文字区域和复用控件见组合清单。

## 来源与检查

母版位于 `designs/ui/full-game/component-sources/`；奖励/装扮、成就/排行、教程/奖励小图母版原生1536×1024，物品槽母版原生1254×1254。每次调用实际附上邮件和组队两张主风格参考，以及当前麻将大厅。完整提示词在 `prompts/full-game/ui/components/`，回执和机械导出脚本在 `work/full-game-ui/components/`。

宿主未披露实际模型与质量，因此逐图 `actualModel`、`actualQuality` 保持 null。配置目标并非实际模型版本证明。组件为美术资源和接入约定，真实客户端交互与服务状态仍待接入。

最终深浅底接触表为 `work/full-game-ui/components/qa/cards-badges-light.png`、`cards-badges-dark.png`、`slots-tutorial-light.png` 和 `slots-tutorial-dark.png`。图像与记录逐项检查见本域 QA。

复现时运行 `work/full-game-ui/components/export_components.py`，随后实际检查最终深浅底接触表，再运行 `finalize_components.py` 同步验收字段；脚本写入的状态不能替代实际视觉检查。

## 精确接入点

领取动作引用旧 `assets/ui/component-compositions.json` 的 `buttonFamilies.primary`，组合清单明确记录 `actionFamilySource`。教程箭头原生396×334，目标对齐点为左上原点像素(350,313)，归一化坐标为(0.8838383838383839, 0.937125748502994)，按x/宽、y/高计算。该像素Alpha245；Alpha>128的最下行是y315、x344—351。此处修正仅涉及接入元数据，PNG内容和哈希保持不变。
